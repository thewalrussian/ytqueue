# YT Queue

Очередь видео с YouTube-подписок. Это PWA без сборки и зависимостей: работает в любом браузере
и устанавливается как приложение на Windows, macOS, Linux, Android и iOS.

## Возможности

- Добавление каналов по ссылке, `@handle` или ID, а также массовый импорт подписок из Google Takeout (`subscriptions.csv`).
- Свои очереди: именованные наборы каналов, между которыми можно переключаться.
- Отметки «просмотрено» и «игнорировать» с отменой; списки просмотренных и игнорируемых, откуда видео можно вернуть.
- Трансляции на отдельной вкладке: «сейчас в эфире», «запланированы», «записи».
- Шортсы не загружаются совсем.
- Встроенный плеер или открытие на YouTube, сортировка, «отметить всё просмотренным».
- Синхронизация между устройствами через Google Drive.
- Экспорт и импорт резервной копии.

## Как это устроено

Данные берутся из YouTube Data API v3. У каждого канала `UC<id>` YouTube ведёт служебные плейлисты:
`UULF<id>` содержит только обычные видео, `UULV<id>` только трансляции, `UUSH<id>` только шортсы.
Приложение запрашивает первые два. Одно обновление стоит примерно 2–3 единицы квоты на канал
при бесплатном лимите 10 000 в сутки.

Все данные (каналы, очереди, отметки, ключ) хранятся в IndexedDB браузера.

## Синхронизация через Google Drive

Данные лежат одним файлом `ytqueue.json` в скрытой папке приложения в Google Drive (`appDataFolder`, scope `drive.appdata`).
Приложению доступна только эта папка. Сервер не нужен: вход идёт через Google Identity Services прямо из браузера.

Синхронизация не перезаписывает данные, а объединяет их:
- для отметки видео побеждает самое позднее изменение;
- состояние трансляции меняется только вперёд: запланирована → в эфире → запись;
- для очереди побеждает последняя правка;
- удаление канала или очереди тоже синхронизируется.

Когда синхронизация запускается:
- при старте приложения;
- через 3 секунды после любого изменения;
- при возвращении в приложение;
- по кнопке ⟳.

Токен Google действует час. Когда он истёк, кнопка ⟳ заново входит одним кликом: браузеры разрешают окно входа только по нажатию.

Настройка (один раз, в том же проекте Google Cloud): включить Google Drive API, настроить экран согласия OAuth
(добавить себя в Test users) и создать OAuth client ID типа «Web application», указав в Authorized JavaScript origins
адреса приложения. Подробная инструкция есть в настройках приложения.

Чтобы на других устройствах ничего не вводить, впишите API-ключ и Client ID в `js/config.js` перед публикацией.
API-ключ, кроме того, сам приходит с синхронизацией.

## Запуск локально

```powershell
.\serve.ps1            # http://localhost:8080/
```

Если скрипты PowerShell запрещены: `powershell -ExecutionPolicy Bypass -File .\serve.ps1`.

## Установка на телефон

Service worker и установка PWA требуют HTTPS. Самый простой вариант — выложить папку на любой
статический хостинг: GitHub Pages, Cloudflare Pages или Netlify. Затем откройте сайт в браузере
и выберите «Установить приложение» (в Safari на iOS: «Поделиться» → «На экран Домой»).
Адрес сайта добавьте в ограничения API-ключа (Website restrictions).

## Структура

- `index.html`, `css/style.css` — разметка и стили.
- `js/app.js` — состояние, обновление, интерфейс.
- `js/yt.js` — клиент YouTube Data API.
- `js/db.js` — хранилище на IndexedDB.
- `js/gdrive.js` — вход Google и чтение/запись файла в Drive.
- `js/merge.js` — объединение данных двух устройств.
- `js/config.js` — ключи по умолчанию для развёрнутой копии.
- `sw.js`, `manifest.webmanifest`, `icons/` — PWA.
